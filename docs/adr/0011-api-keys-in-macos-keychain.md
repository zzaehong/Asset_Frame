# ADR-0011: API 키를 앱에서 macOS 키체인에 저장한다

- 상태: 채택
- 날짜: 2026-11-22
- 관련: [ADR-0008](0008-mac-app-read-only.md) 앱은 읽기 전용, AGENTS 4·9절(비밀은 `.env` 또는 시크릿 매니저)

## 배경

키는 `.env` 평문으로만 두었고, CLI는 프로세스 환경변수만 읽어서 `.env`를 따로 불러와야 했다. 사용자가 앱 안에서 키를 관리하길 원했다(2026-11-22). ADR-0008은 앱이 수집·입력을 못 하는 읽기 전용 뷰어라고 정했다. 쓰기를 열면 기록 경로(CLI)가 둘로 갈라지기 때문이다.

## 결정

1. **예외는 하나뿐이다.** 앱은 프로젝트의 DB·파일을 계속 읽기 전용으로만 연다. 앱이 쓰는 것은 키체인 항목(API 키)의 저장·교체·삭제뿐이다. 수집·예측·채점 실행은 여전히 CLI만 한다.
2. **저장 위치.** 로그인 키체인의 generic password. service는 `local.assetframe.api-keys`, account는 환경변수 이름(`TIINGO_API_KEY`, `FRED_API_KEY`, `KRX_API_KEY`, `ECOS_API_KEY`). 키체인은 AGENTS가 허용하는 시크릿 매니저다.
3. **값은 앱 화면에 다시 보이지 않는다.** 입력은 보안 입력창에서 한 번만 하고, 화면은 저장 여부만 묻는다(속성만 조회, 값 조회 없음). 붙여 넣은 값의 앞뒤 공백·줄바꿈은 제거한다.
4. **CLI 조회 순서.** 환경변수(비어 있지 않으면) → macOS이면 키체인(`/usr/bin/security find-generic-password -w`) → 오류. 값은 명령줄 인자·로그·출력에 넣지 않고 stdout으로만 받는다. Linux·WSL은 환경변수만 쓴다.
5. **격리.** 키체인 접근은 `asset_frame/secrets.py` 한 곳에 두고 `run`·`platform`을 주입할 수 있게 한다. 테스트는 실제 키체인을 읽지 않는다(`tests/conftest.py`).

## 결과와 한계

- 평문 `.env` 없이 키를 둘 수 있고, 환경변수를 따로 불러오지 않아도 CLI가 키를 쓴다.
- 앱이 만든 항목을 터미널의 `security`가 처음 읽을 때 접근 허용 창이 뜰 수 있다("항상 허용"). 앱은 임시(ad hoc) 서명이라 다시 빌드하면 서명이 바뀌어, 이전 빌드가 만든 항목을 바꾸거나 지울 때 로그인 암호를 물을 수 있다.
- 키체인 접근을 허용 창 없이 하려면 개발자 서명과 키 그룹이 필요하다. 개인용 임시 서명 앱이라 하지 않는다.
- macOS 전용이다. 다른 OS는 `.env`를 계속 쓴다.
- 키 값 자체의 유효성(만료·권한)은 확인하지 않는다. 수집 시 오류로 드러난다.
