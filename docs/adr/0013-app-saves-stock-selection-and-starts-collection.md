# ADR-0013: 앱이 개별주 선택을 저장하고 갱신 CLI를 실행할 수 있다

- 상태: 채택
- 날짜: 2026-11-22
- 관련: [ADR-0008](0008-mac-app-read-only.md), [ADR-0010](0010-stock-watchlist-chart-analysis.md), [ADR-0011](0011-api-keys-in-macos-keychain.md), [ADR-0012](0012-scheduled-update.md)

## 배경

개별주 선택 화면은 고른 내용을 텍스트로 만들어 줄 뿐이라, 사용자가 복사해 `config/stocks.toml`에 붙이고 터미널에서 수집해야 했다. 사용자가 선택을 화면에서 저장하고 "지금 수집" 버튼으로 바로 받길 원했다(2026-11-22). ADR-0008은 앱이 읽기 전용이고 수집을 할 수 없다고 정했는데, 이유는 기록 경로(CLI)가 둘로 갈라지지 않게 하려는 것이었다.

## 결정

앱의 예외를 둘만 더한다. 데이터베이스는 계속 앱이 열어 쓰지 않는다.

1. **`config/stocks.toml` 한 파일을 쓴다.** 앱은 티커를 다시 검증(형식 `^[A-Z]{1,5}(-[A-Z])?$`, 중복 없음, 최대 50종목)한 뒤에만 파일을 원자적으로 교체한다. 잘못된 입력이면 파일을 건드리지 않는다. 파일 텍스트 형식은 대시보드 JavaScript·파이썬 로더와 같고, 같은 문자열을 JS와 Swift 테스트가 각각 단언한다.
2. **수집은 CLI를 자식 프로세스로 실행해서만 한다.** 명령은 `<프로젝트>/.venv/bin/python -m asset_frame update --steps stocks,dashboard`로 고정이며 사용자 입력은 명령줄에 들어가지 않는다. 앱은 수집·계산 로직을 갖지 않고, 기록 경로는 여전히 파이썬 CLI 하나다.
3. **출력은 파이프가 아니라 로그 파일**(`var/logs/collect-stocks.log`)에 쓴다. 앱을 닫아도 수집이 이어지고, 앱은 로그 끝부분을 읽어 진행 상황을 보여 준다.
4. **중복 실행 방지.** 시작 전에 CLI가 쓰는 `var/update.lock`을 확인해 스케줄 실행을 포함한 갱신이 돌고 있으면 시작하지 않고 알린다. 중단 버튼은 이 앱이 시작한 수집만 멈춘다(스케줄 실행은 건드리지 않는다).
5. **진행률.** `update`가 `var/progress.json`(퍼센트·단계·종목 수)을 쓰고 끝나면 지운다. 앱은 갱신이 실행 중일 때만 읽어 진행 막대로 보여 준다(스케줄 실행도 표시). 퍼센트는 종목 수를 단위로 세고 다른 단계는 1단위라 시간을 대략 따를 뿐 남은 시간 예측은 아니다.
6. **화면과의 연결.** 웹 화면은 앱이 주입한 메시지 핸들러(`assetFrame`)가 있을 때만 저장·수집·중단·상태 버튼을 보여 준다. 허용하는 동작은 `save`, `collect`, `cancel`, `status` 넷뿐이다. 브라우저로 열면 기존 복사·저장 방식이 그대로다.
6. 수집이 끝나면 앱이 대시보드를 다시 읽는다.

## 결과와 한계

- 선택 저장만으로도 매일 07:30 자동 갱신(ADR-0012)이 새 종목을 받는다. 지금 수집은 즉시 받고 싶을 때 쓴다.
- 첫 수집은 시간당 50요청 제한 때문에 종목 50개에 2시간 넘게 걸린다.
- 앱에서 띄운 CLI는 앱의 환경변수를 상속하므로(Finder에서 열면 거의 비어 있음) 키는 `.env`(`update`가 읽음)나 키체인으로 찾는다. 키체인을 쓰면 허용 창이 뜰 수 있다.
- `.venv`가 없으면 시작하지 못하고 `uv sync --dev --frozen`을 안내한다.
- 프로젝트 경로·환경(`DATABASE_PATH` 등)은 기본값을 따른다. 다른 위치의 DB를 쓰면 잠금 파일 위치가 어긋난다.
- 예측 입력·원장 기록·채점은 여전히 앱에서 할 수 없다.
