# ADR-0012: 데이터를 매일 자동으로 갱신한다(launchd)

- 상태: 채택
- 날짜: 2026-11-22
- 관련: [ADR-0007](0007-ledger-hash-chain.md) 원장, [ADR-0008](0008-mac-app-read-only.md), [ADR-0011](0011-api-keys-in-macos-keychain.md) 키체인, `config/sources.toml` Tiingo 한도

## 배경

수집은 명령을 하나씩 손으로 쳐야 했다(FRED는 시리즈별로, 가격은 ETF·개별주 따로). 사용자가 거시 정보를 포함한 모든 데이터를 주기적으로 받아오길 원했다(2026-11-22).

## 결정

1. **`asset-frame update` 한 명령이 모든 갱신을 한다.** 순서: FRED 11개 시리즈 → ETF 가격(증분) → 선택한 개별주 가격(증분) → 월간 수익률 계산 → 월말 국면 기록 → 대시보드 재생성 → 백업. `--steps`로 일부만, `--dry-run`으로 계획만 볼 수 있다.
2. **한 단계가 실패해도 나머지는 계속한다.** 끝에 성공·실패·건너뜀 요약을 내고, 실패가 있으면 비정상 종료하며 macOS 알림에 실패한 단계 이름만 띄운다. 같은 명령으로 재실행하면 이어받는다(기존 수집의 재개 방식).
3. **원장 기록은 수집이 모두 성공했을 때만 한다.** 영구 기록(ADR-0007)이 낡은 데이터로 만들어지면 되돌릴 수 없으므로, 수집 단계가 하나라도 실패하면 국면 기록은 건너뛴다(계산·화면은 계속). 기록은 기존 `record-regime`(live)이라 같은 달은 한 번만 쓰이고, 달이 끝나 월간 수익률에 새 월이 생겼을 때만 새 항목이 생긴다. 예측·신호 기록과 채점은 자동화하지 않는다(사용자 판단이 들어가는 기록이라 별도 결정).
4. **동시 실행 방지.** `var/update.lock`에 pid를 쓰고, 살아 있는 실행이 있으면 새 실행은 아무것도 하지 않고 끝난다. 죽은 pid의 잠금은 교체한다.
5. **스케줄은 macOS launchd.** `asset-frame schedule install|uninstall|status`가 `~/Library/LaunchAgents/local.assetframe.update.plist`를 쓰고 등록한다. 기본은 매일 07:30(미국장 마감과 Tiingo 일봉 반영 뒤). Mac이 자고 있으면 깨어난 뒤 한 번 돈다. 로그는 `var/logs/update.log`.
6. **키.** 스케줄 실행에는 셸 환경이 없으므로 `update`가 작업 폴더의 `.env`를 읽어 비어 있는 환경변수만 채운다(이미 있는 값은 덮어쓰지 않고 이름만 다룬다). 그다음 키체인(ADR-0011) 순이다. plist에는 비밀을 넣지 않는다.

## 결과와 한계

- 하루 요청은 약 110개(ETF 62 + 개별주 50 증분)로 일일 한도 1000을 넘지 않는다. 75초 간격 제한 때문에 첫 갱신은 ETF만 약 78분, 개별주 50종목이면 합쳐서 약 3.5시간이다. 개별주의 처음 이력은 `ingest-stocks`로 미리 받아 두는 편이 낫다.
- **Mac이 꺼져 있으면 건너뛴다.** 자는 중이면 깨어난 뒤 실행한다.
- **스케줄은 저장소의 현재 작업 트리와 `.venv`를 그대로 실행한다.** 브랜치를 바꾸면 그 브랜치의 코드가 돈다(`update`가 없는 브랜치면 실패). 저장소를 옮기면 `schedule install`을 다시 한다.
- 키체인 키를 쓰려면 터미널에서 한 번 직접 읽어 "항상 허용"을 눌러 둬야 한다. 백그라운드 실행은 허용 창에 답할 수 없다. `.env`만 쓰면 필요 없다.
- 새 월 국면 기록은 월말 다음 날 아침에 자동으로 생기지만, 해당 달의 거시 지표는 아직 발표 전일 수 있다. 기록은 월말 시점에 알 수 있던 값만 쓰는 point-in-time 규칙(`regime_v2`)을 따르므로 실행 날짜와 무관하다.
